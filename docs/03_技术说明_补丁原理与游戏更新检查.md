# 技术说明：补丁原理与游戏更新检查

## 1. 涉及的游戏文件

| 文件 | 内容 | 被哪些功能修改 |
|---|---|---|
| `GameAssembly.dll` | IL2CPP 编译后的游戏代码（x64） | 门派特性随特殊建筑、自创武学每品级9门 |
| `LongYinLiZhiZhuan_Data\il2cpp_data\Metadata\global-metadata.dat` | 类名 / 方法名 / 参数名（v27） | 只读，用于按名字定位方法 |
| `LongYinLiZhiZhuan_Data\resources.assets` | 数据表（TextAsset，CSV） | 合欢殿（BuildingData）、合欢宗主天赋（HeroTagData） |
| `LongYinLiZhiZhuan_Data\globalgamemanagers` | ResourceManager 资源路径表 | 合欢殿（地图造型、内景） |
| `LongYinLiZhiZhuan_Data\sharedassets0.assets` | UIAtlas 图集 | 合欢殿（建造列表图标） |

修改器全部用自己写的二进制读写（`Core.cs`），**不依赖 UnityPy 等第三方库**；只替换目标对象，其余字节保持原样。

### Unity SerializedFile（版本 22）要点
- 文件头大端：metadataSize@20 (u32)、fileSize@24 (i64)、dataOffset@32 (i64)。
- 对象表：pathID i64、byteStart i64（相对 dataOffset）、size u32、typeIndex i32。对象 8 字节对齐、紧密排列，无 TypeTree。
- 替换对象时按 (起点, 大小, 表序号) 稳定排序，重排后面的对象并更新文件头大小。（曾因排序不稳定导致输出不一致，已修复；`--idtest` 可验证原样替换后字节完全相同。）
- TextAsset 原始数据 = 对齐字符串 m_Name + 对齐字符串 m_Script（表内容是 UTF-8 CSV，带 BOM，行尾 `\r\n`）。
- ResourceManager（classID 147）：m_Container = 按字节排序的 (路径字符串, PPtr(fileID i32, pathID i64)) 列表，后接 m_DependentAssets。
- SpriteAtlas：name、m_PackedSprites（PPtr 列表）、m_PackedSpriteNamesToIndex（字符串列表）、其余。

### IL2CPP 定位方法
- global-metadata.dat v27：字符串表@24、方法表@48/52（每条 32 字节：nameIndex@0、paramStart@12、token@20、paramCount@30）、参数表@88、字段表@96、类型表@160/164（每条 88 字节：nameIndex@0、fieldStart@32、methodStart@36、method_count@64、field_count@68）。
- GameAssembly.dll 里搜索字符串 `Assembly-CSharp.dll` 找到 CodeGenModule：+8 方法数，+16 方法指针表；方法地址 = 指针表[token 的 RID - 1]。
- 修改器按「类名 + 方法名 + 参数名」定位（例如 `HeroData.HaveForceFunction(forceID)`），所以游戏更新后地址变化也能自动找到；再用固定的指令特征确认结构没变，不符合就报「不兼容」而不会乱改。

## 2. 各功能的具体修改

### 2.1 门派特性随特殊建筑（GameAssembly.dll）

游戏用 `HeroData.HaveForceFunction(forceID)` 判断「这个角色能否使用 forceID 号门派的门派特性 / 功能」。BuildingData 里特殊建筑的门派功能按钮条件就是 `我&门派功能N`（N = 门派编号）。

原版逻辑（关键部分）：角色所属门派 `belongForceID`（HeroData+0x84）必须等于 forceID，再查一个静态列表。

修改后：
```
force = hero.GetForce(includeServant: false)
area  = force?.MainArea()
return area?.FindBuilding(53 + forceID) != null
```
即「自己门派的主驻地里有 forceID 号门派的特殊建筑」就返回 true。特殊建筑编号 = 53 + 门派编号（53 销金窟 … 72 玄冰池，只有 0~19 号门派有）。53 这个基数是从 BuildingData 里含 `门派功能0-` 的那一行算出来的，不是写死的。

改法：把 `cmp [rbx+X],edi ; jne` 到函数尾声 `mov rbx,[rsp+30h]; add rsp,20h; pop rdi; ret` 之间的指令替换为 47 字节新代码（3 个 call + 判断），其余填 nop。检测标记：函数内出现 `48 8B CB 32 D2 E8`（mov rcx,rbx; xor dl,dl; call）。

其他门派完全不受影响：它们的驻地不会有别派的特殊建筑，而自己的特殊建筑本来就在。

**生效范围（代码确认）**
- 原函数开头的前置判断保留：只对 heroID == 0（主角，HeroData+0x58）返回 true，所以只有主角拥有这些特性，门派弟子没有。
- HaveForceFunction 在游戏里有约 90 处调用，既包括特殊建筑里的门派功能按钮（BuildingData 条件 `我&门派功能N`），也包括门派特性的规则效果，例如：痛饮（DrinkUIController.ManageDrinkBuff）、豪赌、行医 / 妙药（看病、疗伤、医治 NPC）、行乞（AskGiftFromNPC）、天工 / 巧匠（CraftUIController、EnhanceUIController）、禅宗 / 道法（GetMeditationTopic）、马术（ManageHeroHorseMove）、博引（GetIdentifyKnowledge）、杀手（CatchBadFamePlayerEventHappen、StartBeatRandomEnemy）、归宗（GameController.UpgradeSkill）、辩论（DebateUIController）、技艺经验（ChangeLivingSkillExp）等。
- 不受影响的：门派介绍里显示的特性文字（仍是自己门派的）、ForceSpeAddData 这类门派数值加成（来自门派自身数据，存档里是读档时重算的派生数据）。

### 2.2 自创武学每品级 9 门（GameAssembly.dll）

`WorldData.HavePlayerCustomSkill(rareLv)`：遍历 `WorldData.customSkills`（字典，值是 CustomSkillData：skillData@0x10、createHeroName@0x18、createByPlayer@0x20），原版只要找到一个「玩家创建 且 品级 == rareLv」的就返回 true → 每品级只能 1 门。
调用者：`PlotController.StartCustomSkillEntry`（选项旁显示已创建）和 `PlotController.CustomSkillChooseLevel`（选了已创建的品级会被拒绝）。

修改：在匹配处改为计数（用 dil 寄存器，函数开头已清零）：
```
cmp [rcx+34h],ebx ; jne 下一个   ; 品级相同才算
inc dil
cmp dil,9         ; 不足 9 个继续遍历
jb  下一个
```
遍历自然结束时原函数返回 false（状态 0x63），只有中途 break（0x65）才返回 dil，所以不足 9 个返回 false，满 9 个返回 true。共改 16 字节。上限常量 `GamePatcher.MaxCustomSkills = 9`。

### 2.3 合欢殿（resources.assets + globalgamemanagers + sharedassets0.assets）

- **BuildingData** 追加一行，编号 = 表中最大编号 + 1（当前 76），未列出的列复制「金顶」（67）：
  - 类别 6（特殊建筑）、唯一 1、限制区域 999（不匹配任何区域 → 新游戏不会自动生成，只能在存档里解锁后自建）
  - 互动选项：提升内力上限、提升生命上限、宴饮、招女弟子（`招募门派弟子`，男弟子比例 0 时只招女）
  - 每月产出 粮食+150；维护 银钱-100；加成 全员内功2、全员绝技2、内功经验+20%、全员口才2；升级消耗 木料1000、药材1000；建造 20 天
  - 图标列 = 金顶的图标值（地图上用 `skeleton/building/<id>/…` 的骨骼动画）
- **globalgamemanagers**：ResourceManager 里增加 `skeleton/building/76/*`（7 条）指向金顶 `skeleton/building/67/*` 的同一批对象；增加 `textures/background/合欢殿` 指向金顶的内景图。
- **sharedassets0.assets**：UIAtlas 增加 `buildingicon_76`，指向 `buildingicon_67` 的同一个 Sprite（建造列表图标，来自 `AreaController.FreshAreaBuildingButton`）。
- 存档里要把 76 加进顶层 `speBuildingUnlocked` 才会出现在建造列表（修改器「存档」页「解锁合欢殿」）。

### 2.4 合欢宗主天赋（resources.assets）

HeroTagData 追加一行，编号 = 最大编号 + 1（当前 393，要求编号连续）：
`393,合欢宗主,10,Self,<效果>,,,0,0,,,特效,FALSE`
（价值 10、影响自己、不可随机、无领悟需求、大类「特效」）。效果字符串格式 `效果名+数值;…`，效果名必须在 SpeAddDataBase 里存在（修改器安装前会检查）。百分比效果数值写小数（0.2 = 20%）。
角色拥有天赋 = Hero 里 `heroTagData` 有 `{"tagID":393,"leftTime":-1.0,"sourceHero":null}`。

## 3. 安装 / 卸载 / 备份逻辑（Patches.cs → GamePatcher.Analyze / Apply）

1. 对每个文件，用各功能的检测函数判断当前文件是否被改过：
   - 没改过 → 当前文件就是原版。
   - 改过 → 读 `.bak` 作为原版（`.bak` 也被改过则报错，需 Steam 验证完整性）。
2. 每个功能单独在原版上试装一次，失败 = 不兼容（显示原因，不能勾选）。
3. 已安装功能集合重新生成一遍，与当前文件比较，不同 = 「已安装，可更新」。
4. 应用时：目标文件 = 原版依次叠加勾选的功能（DLL：门派特性 → 自创武学；resources：合欢殿 → 天赋）。与当前相同则跳过；第一次改某文件前把原版写成 `.bak`；写临时文件、校验 MD5 后替换。
5. 生成结果是确定的：同样的原版 + 同样的勾选 = 逐字节相同的文件。

## 4. 游戏更新后的检查清单

1. 关游戏 → 修改器「检测」。Steam 更新会用新原版覆盖补丁，状态通常变回「未安装」，旧 `.bak` 会在安装时被新原版替换。
2. 全部能勾选（没有红色「不兼容」）→ 直接「按勾选安装 / 更新」。
3. 安装后可以额外核对：
   - 合欢殿编号、合欢宗主天赋编号是否仍是 76 / 393（界面顶部、日志里会显示）。**如果游戏新增了建筑或天赋，编号会变，存档里引用的旧编号就对不上了**，需要另行处理存档。
   - `--status` 命令行输出。
4. 出现「不兼容」时的含义：
   - 「代码中找不到方法 …」：游戏改了类名/方法名/参数名 → 需要用 `tools\` 重新分析。
   - 「HaveForceFunction / HavePlayerCustomSkill 结构与预期不同」：函数内容变了 → 用 `tools\ndis.py` 反汇编比对后更新特征码。
   - 「建筑表 / 天赋表 / 效果表里找不到 …」：数据表改了列名或删了「金顶」等。
5. 2026-11 更新的核对结果：所有方法签名不变，HaveForceFunction 只有一个与补丁无关的静态字段偏移变化（0x3a8→0x3b0），四项功能全部兼容；建筑 76 / 天赋 393 编号不变；新增内容是私宅练功房的「自创武学」。

## 5. 编译

`source\合欢宗修改器\build.bat`：用 Windows 自带的 .NET Framework 编译器
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（C# 5 语法，已确认可编译），输出 `合欢宗修改器.exe`。

在 Linux / mono 下：
```
mcs -nostdlib -noconfig -target:winexe -out:LongYinMod.exe \
  -r:/usr/lib/mono/4.5-api/{mscorlib,System,System.Core,System.Windows.Forms,System.Drawing}.dll \
  -codepage:utf8 -optimize+ src/*.cs
```
**必须引用 4.5-api 参考程序集**：直接用 mono 自带的 mscorlib 编译，会绑定到 Windows .NET 4.x 没有的 `String.Split(char, StringSplitOptions)` 重载，在 Windows 上运行时报「找不到方法」。
