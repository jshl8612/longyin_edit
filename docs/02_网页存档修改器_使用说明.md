# 网页存档修改器 使用说明

文件：`release\龙胤立志传存档修改器.html`（单文件网页，离线可用，文件不会上传；由 `source\网页存档修改器` 构建）
浏览器：**Edge 或 Chrome**（需要「文件系统访问」功能才能直接写回存档；其他浏览器只能另存）

---

## 两种形式

| | 程序版 `龙胤立志传存档修改器.exe` | 网页版 `龙胤立志传存档修改器.html` |
|---|---|---|
| 放哪里 | 游戏根目录（和 LongYinLiZhiZhuan.exe 放一起） | 任意位置 |
| 打开存档 | 启动后直接显示存档列表，点一个即可 | 拖入 / 选择 Save 文件夹或单个文件 |
| 游戏数据（武功、天赋、门派、地点、人物、建筑名） | 每次启动从游戏文件 resources.assets 读取：游戏更新、合欢宗修改器装的新天赋 / 新建筑都会自动显示 | 内嵌在网页里（整理时的版本） |
| 浏览器 | 自动用 Edge（没有则 Chrome、默认浏览器）的应用窗口打开，没有地址栏 | Edge / Chrome |

两者功能、界面、保存方式完全相同（同一套源码）。

程序版说明：
- 程序在本机开一个只监听 127.0.0.1 的服务提供页面和存档读写，每次启动生成随机口令，其他网页无法访问。
- 关闭窗口后约 20 秒程序自动退出；刷新页面不受影响。
- 只能读写 `Save\SaveSlotN\` 里的 Hero / Save / Info / TempHero 和修改器自己的备份文件。
- 游戏不在程序所在目录时，会依次尝试：合欢宗修改器记住的游戏目录、Steam 库、手动选择。
- 窗口使用单独的浏览器配置（`%LOCALAPPDATA%\LongYinMod\EditorWindow`），不影响日常浏览器。

## 打开存档（网页版）

三种方式（拖进页面或点按钮）：
1. **整个 Save 文件夹** →（推荐）列出所有槽位卡片：人物名、门派、职位、修改时间。点卡片进入。
2. **某个 SaveSlotN 文件夹** → 直接进入这个槽位。
3. **单个 Hero 或 Save 文件** → 旧的单文件模式（Hero = 人物修改，Save = 区域修改）。

槽位模式下顶栏有「人物 / 区域」切换，「换存档」回到槽位列表。

## 人物模式（Hero 文件）

左侧人物列表（搜索、门派筛选），右侧标签页：基本、属性、战斗、武功、包裹、仓库、装备、关系、原始JSON。
天赋在「基本」里增删，天赋列表包含修改器新增的 393「合欢宗主」（**游戏文件装了合欢宗主天赋后才能给人物加**，否则游戏读档会出错）。

## 区域模式（Save 文件）：城市 / 门派驻地扩建

左侧区域列表（城市 / 村镇 / 门派驻地筛选），右侧地块图（上方是地图高行，与游戏画面方向一致）：
- 图例：建筑、空地、残垣、道路、城门、城墙、城外。
- **点格子**：把城墙 / 城外格子改成可建造空地，再点一次撤销。外圈城墙会自动外推（只围绕改动过的格子补墙）。
- 不能改的格子会说明原因：已有建筑、道路、城门；地图最外一圈必须留给城墙；城门周围一圈要保留城墙；只能紧挨城内往外扩。
- 批量：「城墙内圈 → 空地」「尽量扩满整张图」「清除全部残垣」「撤销本区域修改」。
- 残垣（buildingID -1）可以在编辑面板里清成空地，也可以用「清除全部残垣」。

### 建筑编辑

点空地、建筑或残垣，右侧出现「地块」面板：
- **空地**：选建筑类型和等级 →「建造」，直接以成品出现（不需要建造时间）。新建筑的字段结构照抄存档里已有的建筑；仓储系数取本区域建筑的中位数，产出效率 1.0。
- **建筑 / 残垣**：可改建筑类型、等级（0~10）、产出效率、仓储系数；正在建造 / 升级 / 拆除的可勾「立即完成」。点「应用修改」生效。
- 「删除建筑」/「清除残垣」：这一格变回空地。属于人物的建筑（如私宅，belongHeroID ≠ -1）不能删除。
- 「还原这一格」撤销这一格的建筑修改；扩建出来的格子上也可以直接建造。
- 门派特殊建筑、唯一建筑不会检查重复，请自行注意；正厅（中心格）不能编辑。
- 修改过的建筑格显示为蓝色。

已在存档 4/8 的福州、青城驻地实测扩建成功。带内城门的城市（如福州）用「尽量扩满整张图」后城墙显示是否正常，尚未在游戏里确认。

## 存档格式

- 游戏 1.1.3（2026-11 更新）起，Hero / Save / Info 都是 **gzip 压缩的 JSON**，并且省略值为 null 的字段。网页版自动识别：读取时解压，写回时保持原来的格式（压缩存档写回压缩，旧版纯 JSON 写回纯 JSON；gzip 头部照抄原文件）。
- 区域扩建时，新格式存档改出来的空地不写 `"building":null`（与游戏一致），旧格式照旧写。
- 新版存档不再保存气血 / 体力 / 内力上限、护甲、战力评分等派生数值（读档时游戏重新计算）：人物页不显示这些字段，「满血满内」按钮在新存档里隐藏（没有上限值可用）。
- 武功的「基础属性」「招式效果」（speEquipData / speUseData）新版也不保存：编辑武功时这两组改为只读，按武学表和等级算出来显示（数值 ×(1+0.1×等级)，击退 / 拉近不随等级变化，运功效果里的内力上限再 ×2，与旧存档里游戏写出的数值一致）。「突破属性」仍可编辑。

## 保存

- 「保存」：只写入改动过的文件（Hero 和/或 Save），写前在同一文件夹自动备份为 `文件名.yyyyMMdd_HHmmss.bak`。
- 如果文件在打开后被外部改过（游戏存档、云同步），会拒绝写入并提示重新载入。
- 区域修改只替换改动过的地块数据，存档其余内容保持原样（与游戏写出的格式逐字节一致）。

## 注意

- 写存档时最好关闭游戏，或写完后在游戏里重新读档；关闭 Steam 云存档，避免启动时被云端旧档覆盖。
- 存档格式：Save/Hero 都是 JSON（Hero 约 30MB）。

## 构建（改源码后）

程序版：先生成网页模板（不含游戏数据），再编译：
```
python build.py --template
python build_slot.py --template      # → save_editor_template.html（游戏数据位置保留占位符）
..\合欢宗修改器\build.bat           # 同时编译 合欢宗修改器.exe 和 龙胤立志传存档修改器.exe（模板内嵌进 exe）
```

网页版：

`source\网页存档修改器\` 下，用 Python 3 依次运行：
```
python build.py        # hero_editor.html + markup/area.css/gz_io.js/area_mode.js → save_editor.html（加入区域模式、压缩存档读写）
python build_slot.py   # 在 save_editor.html 上加入文件夹 / 槽位模式（slot_picker.html、slot.css、slot_mode.js）
```
输出 `save_editor.html` 即成品。`hero_editor.html` 是原始的人物修改器，其中的游戏数据字典用占位符 `__GAME_DICT__` 表示。

构建需要两个游戏数据文件放在同一目录：`game_dict.json`（武学、天赋、门派、地点、人物名等数据字典）和 `bnames.json`（建筑名表）。这两个文件来自游戏数据，不包含在仓库中。
